# Plan 04-04: Route Handler de Webhook do Resend & Supressão NUNCA-PII

## Objective
Implementar o endpoint de Webhook em `src/app/api/webhooks/resend/route.ts` para receber e processar notificações do Resend (especialmente `suppression.added`), validando a assinatura Svix, correlacionando o e-mail de supressão ao `tenant_id` via `tb_email_log` e registrando Issue no Sentry sem violar a regra de 🔒 NUNCA-PII (zero PII em logs e telemetria).

  <action>
    Criar o arquivo `src/app/api/webhooks/resend/route.ts`:
    1. Ler os headers do Svix (`svix-id`, `svix-timestamp`, `svix-signature`).
    2. Se faltarem headers ou a assinatura for inválida (utilizando `@sparticuz/svix` / `svix` / segredo `RESEND_WEBHOOK_SECRET`), responder 401 Unauthorized imediato.
    3. Se `RESEND_WEBHOOK_SECRET` não estiver configurado, devolver 503 ou logar aviso seguro.
    4. Processar o payload do evento: se `type === 'suppression.added'` (ou bounce definitivo):
       - Extrair o `email` do evento e o `source_id` do e-mail.
       - Se `source_id` estiver ausente / nulo, responder 200 OK sem efeito colateral.
       - Cruzar com `tb_email_log` via `resend_id` ou buscar o `tenant_id` associado.
       - Enviar mensagem/evento sintético para o Sentry (`Sentry.captureMessage` ou equivalente) com rótulo estático `resend:supressao_adicionada` e `tenantHash` anonimizado (HMAC-SHA256 ou hash de via única).
       - **Regra NUNCA-PII:** Garantir estritamente que a string bruta do e-mail, nome ou qualquer dado pessoal JAMAIS seja incluída no payload enviado ao Sentry, nos logs ou no console.
    5. Retornar `response.json({ ok: true }, { status: 200 })`.
  </action>
  <acceptance_criteria>
    - Route handler `POST /api/webhooks/resend` implementado.
    - Rejeita chamadas sem assinatura válida com HTTP 401.
    - Processa `suppression.added` sem vazar PII nos logs/Sentry.
  </acceptance_criteria>
